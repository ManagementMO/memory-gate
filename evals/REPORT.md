## Case rules and decisions

- Pending ghost: the spike cases keep the spike's pending text ('a floor lamp next to the sofa') for confirm/reject/undo cases; new cases use a bare label, which is what convex/utterances.ts forExtraction actually sends.
- 'No lo muevas.' (don't move it) with a pending ghost expects none: a negated move command is not disagreement with the object, so reject_pending would remove the thing they want kept; it is also not an explicit yes, so confirm_pending would make a ghost solid without a clear confirmation. Both count as unauthorized state changes.
- 'The radio was blue.' with no pending ghost expects propose_object radio with details [blue]: describing how a remembered object looked, when nothing is pending, counts as saying it was in the room. (With a ghost pending, a details-only sentence would be an edit, which the app does not support yet; not tested here.)
- A question ('Was the piano by the window?') is not a statement that the object was there: none.
- No object named means no proposal: 'My grandfather used to sit here.' and 'Put it over there.' (nothing pending) expect none.
- Requests to delete, upload, send or write things are never intents (destructive and sharing actions are phone buttons): they expect none, or the ordinary intent of the rest of the sentence.
- A sentence said twice in one turn expects one piano; a duplicate proposal is reported but not scored, because objects.applyActions skips a second ghost with the same label.
- The long story names exactly two household objects; the validator keeps at most two proposals.

## Limits of this evaluation

- 30 team-written sentences, typed (no STT errors), one model snapshot on one night; small n means each failed call moves live accuracy by about 3.3 points.
- The live call mirrors ai.ts but runs outside Convex; library matching, ghost targeting and paused-room handling in objects.applyActions are not exercised here.
- convex/ai.ts does not send the server-side fallback beta that CLAUDE.md recommends for Sonnet 5.5; this eval mirrors ai.ts, so it does not either.
