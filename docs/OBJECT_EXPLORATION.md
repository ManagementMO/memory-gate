# Object exploration in the main memory

This is an additive HUD in the existing `/` journey, including the prepared Red Kite meadow. It does not replace the welcome, companion, captions, social dock, walking, viewpoints, terrain, splat renderer, or controller bindings.

For an immediate comparison or a hardware fallback, append `&objectInfo=off` to the meadow URL. This disables both add-on components, their queries and markers, without changing any configuration file. The default is enabled. Optional information has its own error boundaries, so an unavailable source does not replace the memory.

When a supported rendered object has formed and is visible, a small `Explore · Apify` marker appears beside it. Select the marker to retrieve a short public explanation. A corner card shows the excerpt, publisher, original source link and small `via Apify` credit. The headset renders actual Three.js markers and a native card; it does not depend on a DOM overlay in immersive mode. Trigger/pinch selects the marker; Back dismisses its card. Existing A/B/X/Y/menu and movement controls retain their behavior.

Supported topics: kite/string, flowers/vase flowers, trees. Scene metadata supplies the topic. The prepared meadow also has two authored semantic hotspots for its baked scenery: flowers beside the path and the tree at the existing oak landmark. These appear only when that checked meadow's world ID is active. A generic flower uses daisies as a labeled example; it does not identify the model or scenery as a real species. Arbitrary background splats without this metadata are not treated as recognized objects. New supported objects from the current perspective and approved optional props receive markers too. Other perspectives' ghost objects do not receive this HUD's markers.

Only selecting a marker starts retrieval. The frontend calls authenticated Convex actions, which atomically reserve one topic job per room, start the existing private Source Atlas Actor with `sourceMode: object`, and poll its saved run/dataset. The Actor retrieves bounded HTML from fixed NASA/RHS/Minnesota DNR URLs and returns attributed excerpts. No family story, photo, memory identifier or personal address is sent to Apify. The server checks citations again against the topic allowlist before publication.

No new API key is needed. The existing private `APIFY_TOKEN`, `ALLOW_APIFY_CLOUD=1` and `APIFY_MEMORY_ACTOR_ID` must be pushed with `npm run env:push`. Deploy Actor version 1.3 with `npm run deploy:atlas` before trying the HUD. Each object lookup has a 90-second timeout and a $0.10 maximum request charge; no Maps/Instagram child Actor is used for these topics. Merely seeing an object makes no paid call. Repeated clicks/devices reuse the same saved job. Previously retrieved public references can be reused across rooms for seven days, including offline rooms. Offline rooms without a cached topic cannot start paid requests. Uncertain starts are recorded and never automatically retried.

Object information is public context, separate from a person's recollection. This addition does not change or generate any memory details or rewrite the person's words. Leaving, switching perspective, resting or opening the existing source/story panel closes the info card.

Validation: `npm run test:atlas`, `npm test -- tests/smoke/object-knowledge.test.ts`, Gate typecheck/build, and `node apps/gate/scripts/object-info-check.mjs --live` (explicitly enables bounded Apify retrieval). Browser evidence and live run IDs are recorded separately after verification. Physical Quest testing is still required before claiming headset hardware verification.
